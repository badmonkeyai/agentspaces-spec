# About the specification and the conformance kit

Written for: anyone who builds, reviews, or checks an AgentSpaces implementation, in any language.

This repository is the language-neutral half of AgentSpaces: what every implementation claims conformance *to*.

## The files

| File | What it is |
| --- | --- |
| `SPEC.md` | The normative specification (v0.1.33, draft): identity, peering, discovery, the replicated space, capabilities, the programming model, security, the wire encoding. Java, Python, TypeScript, and Ruby conform to v0.1.33, and SPEC §9.3 records what each still lacks and where the Rust peer stands. v0.1.33 adds the open A2UI records (§6.1a.7), application documents whose vectors live in `agentspaces-a2ui`, and writes down the gossip repair and version-graph rules of 2026-11-09 and 10 (§5.3, §9.4, §11a.4, annex H). |
| `TECH-SPEC.md` | What the reference implementation puts on the wire, byte by byte, and which algorithm runs behind each operation; §1.5 defines conformance and §10 is the checklist a new implementation follows. |
| `REALM.md` | How an Embabel realm's apps, types, producers, APIs, and prompts reach a fleet, and what an `AppCard` with `origin.system` `realm` promises (§5, normative with SPEC v0.1.32). |
| `REGISTRY.md` | The registry of open values: `AppCard.origin` systems and their `attrs` keys, and the well-known `AppCard.formats` entries, with the rule for adding a value. |
| `golden.json` | The golden vectors: 293 named entries today, byte strings and values a conforming implementation reproduces exactly and hostile `adv_*` inputs it refuses. Every entry holds neutral example values; SPEC annex I.3 lists the 25 entries the v0.1.32 AppCard build adds, and annex I.4 the 36 entries of PDT 2. |
| `golden-examples.json` | Non-normative. Realistic example vectors from one console (its widget and visualisation cards, its imported realm apps, its records), in the `golden.json` format, so a product built on AgentSpaces checks its own cards against the core's strict reader. No conformance claim rests on it. The neutrality check (`agentspaces/tools/neutrality-check.sh`, which the core gate runs as `NeutralityGuardTest`) covers `golden.json`, the api and a2ui pins, the core sources, and the specification with these documents, and never reads this file. The console's own generator writes its 7 entries through the console's builders (the core binder, the console's app builder, the core's spiller) and decodes each through the core's strict reader. |
| `negentropy-vectors.json` | The negentropy v1 conformance vectors of PDT 2's store reconciliation, every message of every round, generated by `agentspaces/tools/negentropy/negentropy-vectors.cjs`. |
| `sync-golden.sh` | Copies `golden.json` into the four vendored locations the maintainers own and checks the copies are identical. It never writes the Rust team's copy, since the Rust team re-copies by hand. |
| `quickstarts/` | The README's quick start, `peer_id.py`, and `verify.sh`, which runs it. |
| `tools/docs-lint.mjs` | The documents lint, the same copy in every public AgentSpaces repository: it holds the README to its shape and these documents to their index. |
